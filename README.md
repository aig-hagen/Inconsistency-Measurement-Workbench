# Inconsistency Measurement Workbench

A single-page web application (`site/`) for computing and analysing
inconsistency measures of propositional knowledge bases. The measures are a
JavaScript translation of the inconsistency measures in
[TweetyProject](https://tweetyproject.org) (`org.tweetyproject.logics.commons.analysis`
and `org.tweetyproject.logics.pl.analysis`), including a CDCL SAT solver, MUS/MCS
enumeration, an LP solver and the rationality postulates, all written from scratch
in plain JavaScript. No server, no external libraries.

Open `site/index.html` in a browser (it also works from `file://`), or copy the
`site/` folder to a web server. Fonts are loaded from Google Fonts when online and
fall back to system fonts offline.

The stylesheet and scripts are served from folders named after the version in
`package.json` (`site/css-1.0.0/`, `site/js-1.0.0/`), so browsers never use cached
files of an older version: increase the version and rebuild before deploying a
change. The build also writes the complete source code to `site/im-web-<version>.tar.gz`,
which the page links to.

## Features

- **Knowledge base editor** in TweetyProject syntax (`!`, `&&`, `||`, `^^`, `=>`, `<=>`,
  `+`, `-`) or, switchable, with logical symbols (¬ ∧ ∨ ⊕ → ↔ ⊤ ⊥, with buttons to insert
  them), one formula per line, with per-line syntax errors, duplicate detection,
  formula numbering (φ1 … φn), example library, random generator (arbitrary formulas or
  CNF, seeded), upload (TweetyProject `.txt` or DIMACS `.cnf`, also by drag and drop)
  and download (always in TweetyProject syntax).
- **25 inconsistency measures**, computed in a Web Worker with a per-measure time
  limit and cancel: drastic, MI, MIC, normalized MI/MIC, P, MaxCons (I_M), n-consistency,
  MUS-Var, Df, independent sets, CC, CSP, MCSC, η, contension, hitting set,
  Dalal-Sum/Max/Hit, minimal proofs (Pm), forgetting-based, Iceberg (7 consequence
  operations, count and sum variant), prime-implicant based, fuzzy (minimum or product
  t-norm, T and sum variant). Measures with parameters can be added several times with
  different settings (+ / − buttons). A green or red dot marks whether a value is up to
  date. Export as CSV, JSON, LaTeX or tab-separated text.
- **Conflicts**: minimal inconsistent subsets, minimal correction sets, maximal
  consistent subsets, free and self-contradictory formulas, conflict components,
  formula × conflict matrix and conflict graph.
- **Shapley value**: Shapley inconsistency values (port of `ShapleyCulpabilityMeasure`)
  and removal impact I(K) − I(K ∖ {φ}) for any measure.
- **Postulates**: the 18 rationality postulates of TweetyProject's `ImPostulate`
  classes, checked on all instances derived from the current knowledge base or on
  random knowledge bases, with counterexamples.
- **Incremental**: value of each measure as formulas are added one by one.
- **Compare**: Kendall τ_b rank correlation between measures over random knowledge
  bases, with scatter plots.
- **Worlds**: all interpretations with satisfied formulas and Dalal distances.
- Light, dark and system colour theme (switch in the footer), responsive layout.
- Header links to AIG Hagen, TweetyProject, the source code tarball, the Reference tab
  (also reachable as `index.html#reference`) and TweetyProject's privacy policy and
  imprint.

  02-parser.js             TweetyProject PL syntax parser, knowledge bases, DIMACS reader
  03-sat.js                CDCL SAT solver (MiniSat style, assumptions, unsat cores, incremental)
  04-encode.js             Tseitin encoding, totalizer cardinality constraints, entailment
  05-analysis.js           consistency, MUS / MSS / MCS enumeration (MARCO)
  06-optim.js              simplex LP solver, box-constrained optimiser
  07-measures.js           the 25 measures
  08-tools.js              Shapley values, postulates, sampler, incremental, Kendall τ, worlds

Rebuild after changing `src/`: `node build.mjs` (Node 18 or later, no dependencies).
Run the tests: `npm test`.

## How the measures are computed

Every measure returns the value of the corresponding TweetyProject class, including
its conventions (∞ for hitting set, Dalal-Sum/Max and MCSC with an unsatisfiable
formula and for contension without a paraconsistent model; natural logarithm for the
independent-set measure; NaN where Java divides 0 by 0). Where the validation found
defects in the Java code, the port computes the corrected value (see below).
Exponential naive algorithms of the Java code are replaced by equivalent ones:

| Measures | TweetyProject | This port |
|---|---|---|
| MUS / MCS based (drastic, MI, MIC, nMI, nMIC, P, M, nc, MV, Df, IS, MCSC, Pm) | `NaiveMusEnumerator` + Sat4j | MARCO enumeration on the CDCL solver; same combinatorics on bitsets |
| CC, CSP | ILP (GLPK / lp_solve / Gurobi) | exact branch-and-bound search on the same constraint system |
| η | LP over all 2^n interpretations | LP over maximal consistent subsets (same optimum) |
| Contension | clause removal over atom subsets | SAT encoding of Priest's LP + cardinality bound |
| Hitting set | search over sets of interpretations | SAT with k copies of the signature |
| Dalal-Sum/Max/Hit | all interpretations × models of each formula | bitmask enumeration with distance tables (≤ 22 atoms), SAT encoding beyond |
| Forgetting-based | subsets of occurrence substitutions | SAT with one selector per occurrence + cardinality bound |
| Fuzzy | general optimiser (e.g. CMA-ES) | exact over {0, ½, 1}ⁿ for the minimum t-norm; multi-start local search for the product t-norm |
| Iceberg, prime-implicant based | direct | direct port |

## Validation

`validation/` compares the port with the Java classes (Sat4j, naive MUS enumerator,
GLPK, CMA-ES) on 1000 random knowledge bases and on 300 further bases in which
exclusive or occurs at the top level and over arbitrary operands. `validation/REPORT.md`
contains the results, the examples and the commands to reproduce them.

- **Corrected TweetyProject sources** (commit `2abd5ba` with the corrections of the
  defects listed in the report; uncommitted changes in the TweetyProject working tree):
  over 40 measures and variants, 36545 of 36548 comparisons on the 1000 bases and
  11957 of 11972 on the 300 bases agree; on the remaining 3 and 15 the port finds a
  better optimum of the product fuzzy measure than CMA-ES. No value differs, and Java
  throws no exception. Computations beyond the Java time limit (10 s, retried with
  60 s; Iceberg 5 s) are excluded. 32 direct checks of the corrections
  (`validation/java/FixChecks.java`) pass; 29 of them fail with the original sources.
- **Original sources** (commit `2abd5ba`): the 23 main measures agree on 22540 of 22579
  comparisons; the 39 differences are forgetting-based values that are wrong in Java
  because `Implication.clone()` and `Equivalence.clone()` share their operands. The
  report also covers the fuzzy, Iceberg, SAT-based and Shapley values of the original
  code and the effects of each defect.
